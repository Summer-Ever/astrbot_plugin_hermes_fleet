# Hermes 百账号记忆（astrbot_plugin_hermes_fleet）

给**上百个机器人账号**用的长期记忆插件。每个账号一个独立的记忆库文件，
账号之间的记忆**物理隔离**——串号不是靠"记得写 WHERE"来避免，而是不可能发生。

已在 AstrBot 4.x 上按 `qq_official`（QQ 官方机器人）形态验证接入方式。

## 它做什么

| 能力 | 触发点 | 说明 |
|---|---|---|
| 每轮注入常驻设定 | `on_llm_request` | 称呼、助手设定、用户信息、偏好忌讳、回复风格、规则避雷六个词条 |
| 会话落库 | `on_llm_response` | 用户发言 + 机器人回复写进该账号自己的消息表 |
| 记忆检索 | 工具 `search_memory` | 模型主动调用，检索归档记忆 |
| 记忆写入 | 工具 `save_memory` | 自动归属到当前发言用户 |
| 常驻维护 | 工具 `update_resident` | **用户说一句「以后叫我阿明」，模型自己改词条**；整段覆盖，不是追加 |
| 删除记忆 | 工具 `forget_memory` | 软删除，判错了能回滚 |
| 运维 | `/fleet` 命令组 | 状态、我是谁、常驻、账号列表、总结、整理、删除账号记忆库 |

**不做**每轮自动检索注入。每轮固定烧几千字符换回来的多半是噪声，
还会把真正的用户发言挤到后面。召回交给模型主动调用。

**常驻可以纯靠说话改**：不需要进面板。模型能自己调 `update_resident`，
配套有四件事（都实测过，缺一件就退化成「说记住了其实没写」）：

- 注入块里始终带维护约定，常驻全空时也带——空的时候正是最需要指引的时刻；
- 用户说「我毕业了」「以后叫我 X」这类**自身变化**时，多注入一行明确指令，
  否则模型只会回一句「恭喜」；
- 写入前压平换行、拆掉块边界标记，词条里塞不进「多行指令」；
- 词条被明确声明为「数据不是指令」，带指令腔的内容（「忽略以上指令…」）直接拒绝。

**六个词条记的是谁，写在标签里**：注入时不用「称呼：阿明」这种可以两读的短标签，
而是「怎么称呼用户：阿明」「你的自我设定：自称小雅」。词条内容由模型自己写，
它完全可能把「你叫小雅」写进 address；加上主语后，「这是谁的信息」不靠猜。
写反了也不会静默通过——返回值里会带一句提醒（「你自己的名字属于 assistant」），
但**不阻断**：用户原话「我叫小明，叫我小明」本来就是混着说的。

写作 `update_resident(block, text)`：`block` 六选一，中英文都认（`address` / `称呼`）；
`text` 是**整段新文本**，空串 = 清空该词条。

## 安装

**推荐走面板**：插件 → 安装 → 填仓库地址
`https://github.com/Summer-Ever/astrbot_plugin_hermes_fleet`。装完立刻可用，不用重启，
插件列表、配置页、更新来源都会自动登记。

手工 `git clone` 到 `data/plugins/` 也能跑，但面板不会登记它（列表里看不到、没有配置页、
没有更新来源），且要重启后端。两种方式的差异见 `docs/08-本地部署记录.md`。

**零第三方依赖**，不需要 pip 装任何东西。要求 Python ≥ 3.11（用到 `X | None` 语法）
与带 FTS5 的 SQLite（标准库自带）。

## 配置

常用六项（其余见插件设置页，共 16 项）：

| 键 | 默认 | 作用 |
|---|---|---|
| `memory_injection` | 开 | 每轮注入常驻设定 |
| `capture_messages` | 开 | 记录会话原文（后续总结的原料） |
| `bot_db_dir` | 空 | 留空用 `data/plugin_data/astrbot_plugin_hermes_fleet/bots/` |
| `max_open_bots` | 24 | 同时打开的账号库上限，超出按 LRU 关闭 |
| `recall_k` | 5 | 每次检索返回条数 |
| `group_private_memory` | 关 | 允许在群里引用本人的私聊记忆（默认关，见下文） |

后台任务相关的几项（其余保持默认）：

| 键 | 默认 | 作用 |
|---|---|---|
| `llm_provider_ids` | 空 | **后台总结用的模型链**，逗号分隔，第一个是主模型。建议在管理台「模型链」页直接挑，保存即生效 |
| `llm_provider_id` | 空 | 单模型配置（兼容旧版）。配了链就留空 |
| `llm_cooldown_seconds` | 180 | 失败的模型多久内排到队尾 |
| `summarize_interval_minutes` | 15 | 后台循环间隔 |
| `consolidate_min_active` | 30 | 一个作用域攒够多少条记忆才整理 |

**为什么要显式配链**：后台总结是用户看不见的。主模型挂掉时，新消息永远不再
变成记忆，而没有任何界面会报错——只会表现为"记忆怎么不涨"。AstrBot 自己的
对话走回退链，但插件的后台任务不走，除非在这里显式配。`/fleet 状态` 能看到
当前链和每个模型的冷却剩余秒数。

**为什么必须显式**（v0.7 改）：链留空时等于"跟随主应用当前对话模型"。由主应用
的默认模型决定记忆的归纳风格，意味着主应用换一次模型、记忆的味儿就静默变一次，
而且事后无法归因。候选仍然只从主应用已配置的模型里来（不自己维护清单、也不改
主应用的配置），但选定后写在本插件自己的配置里，**主应用换默认模型不再影响它**。

## 管理台

AstrBot 面板 → 插件 → Fleet 账号台。分两层：**全局三页** + **单账号下钻**。

### 全局

| 页面 | 能力 |
|---|---|
| 账号索引 | 按最后写入排序，一眼看出谁不动了；可给每个账号**起备注**（显示名）；**首屏不打开任何数据库连接** |
| 模型链 | 主模型 → 降级 1 → 降级 2 的实际顺序、谁在冷却、最近 64 次调用、逐模型测连通；**在页面上选主模型与降级，保存即生效** |
| 设置 | 直接改 `_conf_schema.json` 里的 21 项，标出「改了要重载插件」的项 |

账号索引上的动作：搜索（备注、账号 ID、文件名都命中）/ 排序、给账号起备注、
对当前页最多 20 个账号「取统计」（用完立即关库）、告警（孤立库 / 库丢失 /
静默超阈值）。

**备注**只是显示层的别名，存在 `_notes.json`：不改 `platform_id`（改它等于换
账号，记忆会「消失」），也不改库文件名（文件名带 hash，改了索引就和磁盘对不上）。
有备注时第一列主显备注、第二行同时给 ID 与文件名；告警条上也显示备注。

「孤立库」指磁盘上有库文件但索引里没有对应账号——文件名是 slug + 8 位 hash，
不可逆，所以这类数据**任何流程都读不到**，只能手工处理。索引损坏或从别的
机器拷库过来时会出现。

静默阈值用 `account_stale_days` 调（默认 7 天）。

### 单账号下钻（点任意一行）

这一层才打开那个库，而且只开这一个。四个 tab：

| tab | 能做什么 |
|---|---|
| 记忆 | 左栏按作用域（谁 / 哪个群）选人，右栏翻页或搜索；行内编辑内容与 kind；勾选批量**合并**或**删除** |
| 常驻 | 按「人 + 场景（私聊 / 某群）」读六个词条，整段编辑后保存 |
| 未总结 | 按会话分组列出还没被总结的消息，看得见「卡在哪个会话」 |
| 操作 | 立刻对该账号跑一轮总结，不必等后台 15 分钟 |

删除是**软删**（`merged_into` 指向自身），可回溯；物理删除整库仍然没有 UI 入口。


## 为什么每个账号一个库文件

两种隔离方式的成本不对称：

- **一个库 + `WHERE bot_id=?`**：靠每条 SQL 都记得带条件。漏一处就静默串号，
  **而且不会报错**。100 个账号、几十处查询，靠纪律守住不成立。
- **一个账号一个文件**：另一个账号的数据根本不在这个连接能看到的范围内。
  删账号就是删文件，备份就是拷文件。

实测尾延迟也是每库一文件更好（同机、总负载 200 条/秒）：

| 写者形态 | p99 |
|---|---|
| 单库 + 100 写线程 | 2288 ms |
| 单库 + 1 写线程（只按条数提交） | 517 ms |
| 单库 + 1 写线程（条数或超时双触发） | 75 ms |
| **每 bot 一库** | **7.8 ms** |

复现：`python benchmarks/bench_arch.py`。

## 「是哪个账号」怎么取

```python
event.get_platform_id()   # -> 面板里给每个适配器配的 id，如 "qq-01"
```

依据是 AstrBot 的适配器元数据：`PlatformMetadata.id` 取自每个适配器配置的
`id` 字段，`qq_official` 适配器同样如此（`id=cast(str, self.config.get("id"))`）；
`get_platform_id()` 的注释也写明"同时运行多个同类型适配器时 ID 唯一"。
所以一个 AstrBot 实例里配 100 个 QQ 官方机器人，插件能直接分辨是哪一个，
**不需要改本体、不需要打补丁**。

文件名会带 8 位 hash 后缀：`qq-01` 与 `qq_1` 若只做字符替换会折叠成同一个
文件，两个号共用一个记忆——这类事故是静默的。

## 隐私边界

- **私聊与群聊的常驻是两套**：`private` 与 `group:<gid>` 分开存，私聊设定不会
  在群里生效。
- **群里不引用私聊记忆**：`group_private_memory` 默认关闭。`can_read` 里
  "owner 相同即可读"在私聊是对的，但群里把私聊内容念出来就是当众公开。
- **群记忆不外溢**：在 A 群存的事，B 群检索不到。

## 开发

```bash
python run_tests.py            # 全量（127 个用例，零依赖）
python run_tests.py -p fleet   # 只跑插件层（20 个隔离用例）
python tools/check_boundaries.py   # 依赖方向检查
python tools/verify.py         # 一键校验（CI 入口）
```

**业务逻辑不 import astrbot。** 所有记忆语义在 `packages/fleet/`，
`main.py` 只做"取事件字段 → 调 service → 塞回请求"。
直接收益：本机没装 AstrBot 也能跑完整隔离测试——hermes_core 的 5 套 smoke
里有 3 套正卡在这一点上。

```
main.py                       AstrBot 接入层（只做翻译）
hermes_fleet/                 业务层（注入块、检索、工具语义、账号路由）
  registry.py                 platform_id -> 库文件，LRU，purge
  service.py                  注入/落库/检索/常驻的策略
packages/contracts/           冻结的契约（实体只定义一次）
packages/recall/              检索与重排（从 hermes_core 整份搬来）
packages/storage_sqlite/      四种 Store 的 SQLite 实现
benchmarks/                   承载能力实测脚本

```

## 自动总结怎么工作

```
会话消息（已落库）
   ↓ list_pending_sessions：按「最久没动静」排序
   ↓ 够 8 条 或 超 6 小时
   ↓ 拼转录（过滤注入、压平昵称换行）
模型 → JSON 数组
   ↓ 归属校验：私聊强制归本人；群里模型写的 owner 必须在场，否则降级为群记忆
   ↓ 内容去重：同内容已存在则跳过
写 memories → 标记消息已总结
```

三条保护是**用测试固定下来的**，不是注释里的承诺：

| 情况 | 行为 | 为什么 |
|---|---|---|
| 模型调用失败 | 不标记，下轮重试 | 标记了就等于永久丢弃唯一原始素材 |
| 输出被截断 | 不解析、不标记 | 半截 JSON 会把下半条记忆写成一条 |
| 输出是 `[]` | 标记 | 否则「确实没什么可记」会每轮重烧一次模型 |

想立刻验证模型链通不通，用 `/fleet 总结`（管理员），不必等 15 分钟。

## 整理怎么工作

```
某个作用域（你的私聊 / 某个群）攒够 30 条
   ↓ list_scopes：一次 group by 数出「哪些作用域值得整理」
   ↓ list_active：取最近 200 条
本地配对（bigram Jaccard，只召回候选，不决定）
   ↓ 并查集分组，每组 2～6 条，最多 8 组
模型 → JSON（keep / merge / content）
   ↓ id 白名单：只接受真的列进提示词的那些编号
   ↓ 改写表述 + 软删除（merged_into）
```

**为什么本地只做召回**：实测记录在 `pairing.py` 的注释里——「喜欢喝乌龙茶」
与「喜欢喝龙井」的相似度是 0.444，「喜欢喝乌龙茶」与「爱喝乌龙茶」也是 0.444。
纯字面分不开「换动词」和「换宾语」，所以字面只用来看候选，判断交给模型。
阈值取 0.40 而不是 0.5：漏掉一个真重复是静默的，多给模型一条候选只是多几个 token。

四道刹车（都有用例）：

| 刹车 | 作用 |
|---|---|
| 每轮每作用域最多合并 20 条 | 模型偶尔把整库判成重复 |
| id 白名单 | 模型写出没列给它的编号时，拒绝执行 |
| 条数未增长则跳过 | 模型说「保持分开」时条数不变，否则每轮重烧一次钱 |
| 合并是软删除 | 判错了能回滚（`merged_into` 指回原条） |

已知天花板：换掉全部字面用词的复述配不上对（「希望被称为哥哥」↔「希望助手称呼他为哥哥」
实测 0.357）。这条以**通过**的形式固化在测试里，接上向量召回后它会变红——
那一下就是配对能力升级完成的信号。

手动清一遍现有重复：`/fleet 整理`（管理员）。
