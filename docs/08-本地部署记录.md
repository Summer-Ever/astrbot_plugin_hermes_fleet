## 部署方式：走面板的 GitHub 安装入口

**没有**手工 `git clone` 到 `data/plugins/`。原因：手工拷目录后，面板不知道这个插件
的存在（不会出现在插件列表、拿不到配置页、也没有更新来源），还得重启后端。

实际调用的是面板接口（用 `dashboard.jwt_secret` 现签一个短时效令牌）：

```
POST http://127.0.0.1:6185/api/v1/plugins/install/github
{"repository": "https://github.com/Summer-Ever/astrbot_plugin_hermes_fleet"}
```

几个容易踩的点：

- **不要用 `/plugins/install/git`**。它对 github.com 地址会直接拒绝：
  `该地址应通过 GitHub 仓库安装入口处理。` 两个端点分工不同。
- 面板接口是 `/api/plug/<插件名>/<路由>`，**不是** `/api/v1/plugins/...`。
  我第一版探测把两者混了，拿到 404，很容易误判成"接口没注册"。
- 页面 URL 带一次性 token（`/views/fleet/_t/<token>/`），不能直接拼路径访问。

## 面板里提示「没有连上 AstrBot 面板，接口不可用」

页面本身打得开、样式也正常，但顶上一条横幅说接口不可用，按钮全灰。**不是没从面板进**，
是插件页脚本根本没拿到桥接对象。

AstrBot 的桥接机制比看上去脆，两处都能让页面「假死」：

**一、桥接脚本的注入点在 `./app.js` 之后。**

`PluginPageService.process_plugin_page_html()` 是这么干的：

```python
processed_html = processed_html.replace("</body>", f"{bridge_tag}</body>", 1)
```

也就是说 `bridge-sdk.js` 在 `</body>` 前、**在我们自己的 `app.js` 之后**加载。
原来的 `app.js` 第一行就 `const bridge = window.AstrBotPluginView || ...`，
脚本执行时那个对象还不存在，常量被冻结成 `null`，`init()` 一检查就判失败。

改成惰性读取 + 启动时等 1.5s：

```js
const getBridge = () => window.AstrBotPluginView || window.AstrBotPluginPage || null;
// init(): await waitBridge(1500) 超时才显示横幅
```

**二、`index.html` 里不能出现第二个 `</body>`——哪怕在注释里。**

修第一处时顺手在注释里写了「注入在 `</body>` 之前」这句话，于是：

- 面板替换的是**第一个** `</body>`，命中注释里的那一个；
- `<script src=".../bridge-sdk.js?asset_token=...">` 被塞进 `<!-- -->` 内部，浏览器不执行；
- 后面的正文 `前，且 src 里带 ...` 反而漏到页面上成了可见文字。

所以这个文件里任何位置都不能写 body 的闭合标签字面量。

**三、桥接地址不能手写。**

`/api/plugin/page/bridge-sdk.js` 走 query 令牌校验（`plugin_page_auth.py`，
"bridge SDK script still authenticates here, via a query token"）。
手写裸 `<script src>` 会 401；面板注入时会自动拼 `?asset_token=...`。

### 怎么确认修好了（不靠肉眼刷新）

用 `dashboard.jwt_secret` 现签一个 `plugin_page_asset` 令牌，直接抓页面 HTML
（脚本在 `_preview/verify_page.py`）：

```
bytes 4417 | app.js@ 3968 | bridge@ 3718   ← 3718 是注释里第一次提到桥接脚本
asset_token in src: True
---- tail ----
  <script src="./app.js"></script>
<script src="/api/plugin/page/bridge-sdk.js?asset_token=eyJhbGciOi..."></script></body>
</html>
```

判据看**尾部实际标签**的位置，不要用 `str.find` 的首个命中（注释会干扰）：
桥接标签在 `app.js` 之后、在真正的 `</body>` 之前，`src` 里带 `asset_token`。

顺带确认了三件事：`/api/plugin/page/bridge-sdk.js` 200（7992 字节，含
`AstrBotPluginView`）；令牌化路径下的 `app.js` 200（17671 字节）；
页面 URL 里的插件标识是**完整目录名** `astrbot_plugin_hermes_fleet`，
用 `hermes_fleet` 取页面会 404——桥接按插件名前缀拼
`/api/v1/plugins/extensions/<name>/<endpoint>` 时用的也是完整目录名。

### 护栏

`tests/test_web_ui_contract.py`（5 个用例）把这三条钉住了：入口引用 `./app.js`、
`</body>` 只出现一次、不手写桥接地址、桥接对象不缓存成常量、启动时等待桥接。
这类断言看着像挑字眼，但每一条都对应一次真实的「页面一片空白」。

## v0.7：账号备注 + 总结模型解耦

### 一、备注：`_notes.json`，不碰库也不碰文件名

`BotRegistry` 多了一份旁挂表，`accounts()` 的每一行带上 `note`。
选择「不改文件名、不改 platform_id」的原因见 `docs/07` 的 3.1 节：改 id 等于换
账号（记忆会「消失」），改 hash 会让索引与磁盘对不上。

实测（真实宿主，用现有账号 `default_1905730713`）：

```
POST notes {note: "  客服号\n（生产）  "} -> 200 {"note":"客服号 （生产）","trimmed":true}
POST notes {note: "长"*300}              -> 400 备注太长（最多 40 个字符）
GET  overview                            -> items[0].note = "客服号 （生产）"
GET  overview?q=客服                     -> total 1（按备注命中）
GET  overview?q=不存在的人               -> total 0
GET  account?platform_id=...             -> note 字段同值
POST notes {note: ""}                    -> 200，_notes.json 变回 {}
```

`trimmed: true` 是有意暴露的：输入里的换行被压成空格、首尾空白被去掉，
不告诉用户的话，他会以为存进去的就是原样。

### 二、总结模型：显式选，且立刻生效

`packages/fleet/chain.py`（纯逻辑，可脱机单测）+ 管理台「模型链」页的编辑器。
候选来自 `context.get_all_providers()`，只读主应用，不改它的任何配置。

实测：

```
GET  providers -> 200 catalog 3 个：[nemotron(free), qwen3.7-flash, qwen3.8-flash(当前默认)]
                 source_text = 已显式指定（与主应用解耦）
POST models/chain {primary: "不存在/model"}        -> 400 AstrBot 里没有这些模型：不存在/model
POST models/chain {primary: qwen3.8, fallbacks:[qwen3.8]}
                                                    -> 400 「…」重复了：主模型不能同时出现在降级里
POST models/chain {primary: qwen3.8, fallbacks:[qwen3.7, nemotron]}
                                                    -> 200 applied:true，链 3 个，config 未变
GET  config                                        -> 200，5 组 21 项
```

热切换是真的换了实例：`rebuild_provider()` 重建 `FallbackProvider`，并把
`summarizer.llm` / `consolidator.llm` 的引用一起换掉（它们持有的是构造时传进去
的值，只换 `self.provider` 会出现「保存了但总结还在用旧模型」）。

### 三、踩到的坑：重载插件不会重载 `packages/` 下的辅助包

给 `BotRegistry` 加了 `set_note` 之后，重载插件，`POST notes` 直接 500，
而 `/models` 这些新接口都正常。原因是**新旧代码混跑**：

- AstrBot 的重载只清理 `data.plugins.<插件名>` 前缀的 `sys.modules` 项；
- 本插件的辅助包是 sys.path 注入后以顶层名（`hermes_fleet`…）导入的，
  不匹配那个前缀，于是 `main.py` 是新的、`hermes_fleet.registry` 还是旧的；
- 表现就是「新方法不存在」→ AttributeError → 500，代码看着完全正确。

修法在 `main.py` 里：`_purge_stale_packages()` 在导入任何 `hermes_*` 之前，
把**文件位于本插件目录内**的同前缀模块从 `sys.modules` 摘掉。只摘自己目录下的，
避免误删同名插件（hermes_core 用的是 `modules.*`，不受影响）。

这个坑对分发很关键：面板里「从 GitHub 更新」走的是重载而不是重启，任何一次
改了 `packages/` 的更新，用户都会遇到同一类 500。加上自动清理后，重载即等价于
一次真正的更新。

## 0.7.1：常驻的「说话就能改」补齐

用户问了一句很准的话：*"常驻记忆你是不是没有参考 hermes core，在那里用户是可以
直接通过自然语言让 ai 自己编辑常驻记忆的。"*

实际情况是：`update_resident` 工具第一版就在（组件注册表里能看到），但 core 围绕
它的四件配套一件都没搬。缺的不是能力，是**引导**——模型知道自己有这个工具，却
不知道自己该在本轮用它，于是回一句「好的，记住了」就结束，词条里什么都没有。

补齐清单（`packages/fleet/src/hermes_fleet/resident.py` 新建）：

| 配套 | 补齐后 |
|---|---|
| 边界声明 | 注入块首尾成对，词条被定义为「数据不是指令」 |
| 状态变化信号 | `我毕业了` / `以后叫我 X` 命中时追加一行「逐条核对词条」 |
| 写入侧净化 | 压平换行/零宽字符，拆掉块边界标记 |
| 指令腔拒绝 | `忽略以上指令…` 直接拒，并告诉模型原因 |
| 词条别名 | `称呼` / `user` / `用户偏好` 都认 |
| 标签主语 | `- 称呼：阿明` → `- 怎么称呼用户：阿明`、`- 你的自我设定：…` |

最后一条是用户追问出来的："称呼有点歧义，AI 怎么知道这里的内容是自己的身份
还是对用户的称呼？" 确实两读——词条内容由模型自己写，它完全可能把「你叫小雅」
写进 address。修法是把主语写进标签（`INJECT_LABELS`，界面仍用短标签），并在
写反时回一句提醒（`direction_advice`，不阻断：用户原话「我叫小明，叫我小明」
本来就是混着说的）。

**顺带修掉一个真 bug**：注入块超出 4000 字预算时原来是对整串 `clip`，会把
`[/记忆系统上下文]` 一起切掉——模型看到的是一个没有闭合的块。现在预算在渲染
时按词条分配，先丢尾部词条，结构行永远保留（有两条用例钉住）。

验证到什么程度：

- 323 用例全绿（新增 `test_resident_dialog.py` 26 条）。
- 注入块实样已在本机跑出来对过：空常驻也带维护约定、群聊多一行场景限定、
  说「我毕业了」多一行核对指令、写指令腔被拒并给出中文原因。
- **没验证的一环**：真实 QQ 里对机器人说「以后叫我阿明」，看它是否真的调了
  工具。这取决于主模型是否遵守工具描述，本地测不出来。

为此加了 `/fleet 常驻`（只读）：能看到当前场景六个词条的实际内容，空槽也列出来。
以后用户怀疑「它到底记没记住」时，不必再进面板翻库。

## 0.7.2：注入位置可配

问题："常驻记忆是属于用户提示词还是系统提示词？" 答案是**用户提示词**——
`on_llm_request` 里拼成临时 `TextPart` 塞进本轮用户消息（`mark_as_temp`，
不进会话历史），只有老版本没有这个能力时才退回 `system_prompt`。

这个默认值是有意的，但也确实有人需要另一种：常驻里的「规则与避雷」放在用户
消息里，模型只当资料看，不是硬约束。所以加了开关：

| `inject_to_system_prompt` | 落在哪 | 权威性 | 代价 |
|---|---|---|---|
| 关（默认） | 用户消息的临时片段 | 资料 | 规则类词条不被当命令 |
| 开 | `req.system_prompt` 末尾 | 与人格同级 | 词条正文可能来自历史对话，指令腔更易被当真；系统提示词缓存按段失效 |

实现要点：

- `resident.append_system_prompt()` 纯函数：只追加尾部、先 `rstrip()` 再去掉
  空行、**幂等**（用 `INJECT_OPEN` 判断是否已拼过——一次发言可能走多轮工具
  循环，钩子会被叫多次，重复拼会让系统提示词一轮一轮变长）。
- 放置逻辑收进 `_place_block()`，钩子只管取块和去重，两条路不再各写一遍。
- 顺带修一个静默 bug：插件里所有开关原来写成 `bool(self._get_cfg(...))`，
  而 `bool("false")` 是 `True`——手改配置或从别处拷 `cmd_config.json` 留下
  字符串 `"false"` 时，面板上关掉了、行为还开着，且不报错。现在统一走
  `settings.as_flag()`，读不懂就回默认值。

验证：

- 352 用例全绿（+7 `append_system_prompt`、+6 注入位置/`as_flag` 契约、
  +1 README 配置项计数）。
- 用 `ast` 从 `main.py` 里**抽出 `_place_block` 源码**执行（不复制逻辑）实测：
  关闭时 `system_prompt` 原样不动、`extra_user_content_parts` 多一条且
  `mark_as_temp=True`；打开时块以人设开头、以 `[/记忆系统上下文]` 结尾、
  中间恰好一个空行、`extra_user_content_parts` 为空；重复放置两次块只出现
  一次；配置写成字符串 `"false"` 时仍走用户提示词。
- **没验证的一环**：真实宿主上系统提示词注入的实际效果。`astrbot` 本地装不了，
  `on_llm_request` 跑不起来；能证明的只是放置逻辑本身，不是宿主链路。

## 0.7.3：维护提示词从「听命令」改成「对不上就改」

用户的反馈很具体：*"有时候比如用户说了什么信息，但是和常驻记忆冲突的时候，
也要去更新常驻记忆。"*

原判据是 core 那一版：「用户要求记住、修改或忘掉」才写。而真实漏更新的句子
几乎不长这样——用户只是随口说「我现在在深圳」，词条里写着杭州，模型回一句
「好的」就过去了，画像永久停在杭州。它没有违反任何指令，只是没人告诉它
「这句话算更新」。

改了两处：

1. **判据写进常驻约定**：不是「用户有没有说『记住』」，而是「哪句话更新」。
   并列出三种触发：明确要求 / 说到的现状与词条对不上 / 同一件事说得更具体。
   工具描述同步改写（工具的 docstring 也是提示词，只改注入块等于改了一半）。
2. **动态提示按需出现**，分两级，只取一条：
   - `conflict_signal()`：从词条抽实体，命中就点名「与「用户的客观信息」相关」。
   - `drift_note()`：兜底「近况词 + 第一人称 + 已有画像」的泛情况；明确的变化词
     （毕业、以后叫我）仍走强措辞，且不要求已有画像——那时该做的是新建。

降噪是这轮的主要工作量，因为提示频繁出现等于没有提示：

| 噪声 | 处理 |
|---|---|
| 群聊里「群里」天天出现 | 长段里的 2-gram 只是「碎片」，单命中不算数，要命中被标点切开的独立实体（杭州、做客服） |
| 「现在这段代码报错」 | 近况词必须与第一人称同句 |
| 词条全空却让人「核对」 | 没有画像时不发近况提示（那时是新建） |
| 两行叮嘱挤在一起 | 精确命中时不发泛化提示 |

验证：367 用例全绿（+15）。用真实样例逐句跑过——“我在杭州上班”→ 点名
「用户的客观信息」；「我现在在深圳上班”→ 泛提示；「现在这段代码报错」→ 不触发；
「群里有人刷屏了」→ 不触发；「我结婚了」「以后叫我小明」→ 走强措辞。

已知局限：**字面不重叠的冲突抓不到**。用户说「不对，我在做前端了」，词条写
「做客服」——两句没有一个共同实体，也没有变化词，不会触发。要解决得靠语义
判断（比如每轮都让模型自己比对），成本远高于收益，暂不做。常驻维护约定里
那句「闲聊里给的新信息也要落进词条」是留给模型的兜底：它读了整段对话，比
字符串匹配更可能发现这种冲突。

## 0.8.0：提取记忆（用户主动导出）

需求：*「用户对某机器人发出提取记忆指令后，系统自动将和该账号与该机器人相关的含有常驻记忆、归档记忆、聊天原文的文档发送」*。

入口两个，同一个流程：`/提取记忆` 与 `/fleet 提取记忆`，后者可带用户标识（仅管理员）。
默认只导自己——这条不是保守，而是因为文件里含聊天原文。

文档结构：概览表 → 常驻记忆（按私聊/各群分组，标签带主语）→ 归档记忆（跨场景，软删的不在内）→ 聊天原文（时间正序，按会话分组）→ 说明。
落盘用显式 UTF-8（Windows 默认 cp936 会把 emoji 写坏），附件名只用 ASCII，
组件同时带 `file` 与 `url=file:///...`——OneBot 只给裸路径会报 retcode 1200。

### 最重要的坑：群聊配错回复

群会话的 session_id 是全群共享的。第一版在 SQL 里就写了
`owner_id=? or role='assistant'`，结果群友的发言行被滤掉，跟着它的机器人回复
看起来就像「一条没有上文、只能算到我头上的回复」。真实 SQLite 复现：
alice 与 bob 同群各说一句，导出 alice 时把「回复 bob」也带了出来。

修法是**取数不过滤行**：先取该人参与过的会话的全部行（倒序窗口 = 上限 × 8），
再由纯函数 `pair_replies()` 逐行看「这条会话上一条用户发言是谁」来决定
机器人回复归谁，最后截到上限。群友的发言永远不写进文档。

### 验证

- 新增 `packages/fleet/tests/test_export.py` 16 条：渲染/文件名/过期清理纯逻辑，
  以及真实 SQLite 的「两人同群导出不串话」「本人发言与回复都在」。
- 新增 `tests/test_export_contract.py` 12 条源码契约：两入口共用流程、
  管理员检查在取数之前、`File` 带 url、显式 UTF-8、无 SQL 泄漏到 main.py、
  `render_document` 不与数据字典重名（实际踩过 TypeError）。
- 395 用例全绿（367 → 395：+16 导出、+12 契约）。
- 配置项 22 → 25（新增 `export_enabled` / `export_max_messages` / `export_keep_days`），
  README 的计数用例同步改。

### 仍未验证

真实宿主上的**文件发送**：本机装不了 astrbot，`on_llm_response` / `chain_result`
跑不起来。按 AstrBot 4.x 文档构造组件并做了逐级降级，但 OneBot / QQ 官方
适配器是否都能收这个文件，要装上后发一次 `/提取记忆` 才知道。平台不支持时
会退化成一条带本地路径的文本提示，不会静默失败。

## 同步到运行插件 & 命令被 LLM 吃掉的问题（2026-11-26 00:51）

**背景**：这一轮 8 个 commit（v0.7.1 → v0.8.0）此前只在工作区，`origin/main` 落后 8 个，
运行插件目录 `~/.astrbot/data/plugins/astrbot_plugin_hermes_fleet/` 一直是 v0.7.0。
用户在 QQ 里发 `提取记忆` / `/提取记忆`，日志显示消息进了 `event_bus` 后直接走
`tool_loop_agent_runner`（LLM 调 `search_memory`），命令 handler 根本没被触发——
因为那个版本里压根没有 `提取记忆` 这条命令。

**同步方式**：GitHub 在此环境不可达（`curl` 超时，`github_http=000`），面板的
GitHub 安装入口走不通。改为从工作区 `tar` 覆盖代码文件到插件目录（排除 `.git` /
`__pycache__` / `.pytest_cache`），保留面板生成的 `.astrbot-plugin/` 元数据。

**踩到的坑（重要）**：同步完只重载了一次，日志出现
`Plugin ... (v0.8.0)`（读 metadata.yaml）但 `main.py:786: [hermes_fleet] v0.7.0 已加载`
（执行代码）——metadata 是新的、执行的是旧字节码，`__pycache__` 里的 `.pyc` 还在。
现象就是「面板显示新版本，功能却还是旧的」，极具迷惑性。

修法两步：
1. `find . -type d -name __pycache__ -prune -exec rm -rf {} +` 清掉插件目录所有字节码；
2. 通过面板 API 真正重载。

面板重载接口（本机实测，两种写法都 200）：
- `POST /api/v1/plugins/reload`，body `{"plugin_id": "astrbot_plugin_hermes_fleet"}`
  （注意字段是 `plugin_id`，不是 `name`；传 `name` 会 422）
- 或 `POST /api/v1/plugins/astrbot_plugin_hermes_fleet/reload`，body `{}`
- 鉴权：`Authorization: Bearer <JWT>`，payload 用 `{"username": <dashboard.username>, "exp": ...}`，
  HS256 + `cmd_config.json` 的 `dashboard.jwt_secret` 现签（`cmd_config.json` 有 UTF-8 BOM，
  读取要用 `utf-8-sig`）。payload 用 `user` / `sub` 都是 401，只有 `username` 通过。

重载后日志正确：`main.py:1030: v0.8.0 已加载`、命令 `export_memory` /
`fleet_export_memory` 已注册。

**端到端验证**（宿主解释器 `D:/AstrBot/backend/python/python.exe`）：真实账号
`default_1905730713` 导出 6 条常驻 + 8 条归档 + 44 条原文，生成 9882 字节 Markdown，

## 0.9.0：导出拆两份 + 可导入复原（2026-11-26）

用户两点反馈：① 原文本地都有，直接全量发，单条只留文字、加年月日，唯一
上限设 100MB（超了提示联系管理员）；② 原文和记忆配置拆成两份，记忆那份
要能导回去复原配置。

**两份文件**（同一次导出一起发，先小后大）：

| 文件 | 内容 | 用途 |
|---|---|---|
| `hermes-memory-…` | 常驻 + 归档，开头 `<!-- hermes-import-v1 … -->` JSON 块 | 人读 + 机器导入 |
| `hermes-chat-…` | 纯原文，一条一行 `[YYYY-MM-DD HH:MM:SS]`，全量 | 归档/阅读 |

关键改动：

- `export_owner` 的 `max_messages` / `max_memories` 默认 0 = 全量；
  `transcript` 与 `list_by_owner` 都改成 `limit<=0` 时不加 SQL limit。
- 单条原文不再压到 800 字——用户明确要求全量，压平成一行只是格式需要，
  正文一字不删。群友过滤 `pair_replies` 仍保留（这是隐私边界，不能因为
  "直接发出"就撤掉）。
- 100MB 用 UTF-8 **字节**算（`check_export_size`），超限一个文件都不发，
  避免只发一半。
- 导入块只认文档开头的定界注释，人改了下面的 Markdown 排版不影响解析。
- `/导入记忆` + File 附件：`get_messages()` 找 File 组件，`await get_file()`
  拿路径。常驻按词条整段覆盖，归档**追加**（不按来源 id 去重——那是另一
  台机器的 id，对号入座会串库）；全局/公开记忆降级为本人私有，防止一份
  文件就往所有人库里写东西。

验证：422 用例全绿（新增 11 条）。往返测试用真实 SQLite：A 账号导出 →
B 账号导入 → 再导出，常驻与归档都在、owner 是 B、来源全局记忆被降级。
契约测试钉住"先解析后写入""导入前查文件大小""两个入口共用流程"。

**未验证**：真实宿主上 File 附件的接收与发送（QQ 官方适配器）。本机没有
astrbot、`get_file()` 的下载路径跑不起来，只能靠源码契约。
